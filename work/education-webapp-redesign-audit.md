# 문단 흐름 수리소 초기 리디자인 감사

- **작성일:** 2026-08-30
- **감사 시점:** 코드 변경 전 기준선
- **대상:** `/Volumes/ External Drive 256G/Dev2/codex/paragraph-flow-repair-shop`
- **감사 방식:** 저장소 코드·문서·테스트 읽기, 로컬 빌드/검사, Codex 인앱 브라우저의 실제 학습 흐름 관찰
- **미포함:** VoiceOver, 교사 승인, 학생 사용자 테스트, 배포 후 실사용

## 1. 제품·기능 기준선

현재 앱은 정적 Vite/React/TypeScript 앱이며, 여섯 개의 고정 미션을 `useReducer`로 진행합니다. 콘텐츠와 판정은 `src/content/missions.ts`, `src/domain/paragraphEvaluator.ts`, 상태 전환은 `src/app/sessionReducer.ts`가 담당합니다. 서버·로그인·외부 AI·분석·광고·쿠키·브라우저 저장은 제품 계약상 없습니다.

기준 학습 경로는 다음과 같습니다.

```text
입장 → 전체 읽기/첫 판단 → 중심 문장 → 순서 수리 → 관련성 → 연결 관계 → 근거 설명 → 6개 미션 기록
```

기능 계약과 테스트는 전반적으로 분리되어 있고, 이번 감사의 핵심은 “기능을 바꾸지 않고 학습자가 현재 작업과 다음 행동을 더 빨리 이해할 수 있는가”입니다.

## 3. 실제 화면 관찰

로컬 `npm run dev -- --host 127.0.0.1 --port 4173` 실행 시 기존 점유 포트 때문에 Vite가 `http://127.0.0.1:4175/`에서 기동했습니다. Codex 인앱 브라우저의 기준 viewport는 1280×720입니다.

### 입장 화면

- 실제 본문은 약 880px 중앙 열에 있어 데스크톱 양쪽 공간이 크게 남습니다.
- `paper-repair-workbench.webp`의 빈 둥근 사각형·연결선이 실제 미션 카드와 겹쳐 가짜 조작면처럼 보입니다.
- 브랜드가 작고, 학습 목표·6개 미션·시작 버튼의 시각 위계가 약합니다.
- 헤더와 본문에 업데이트 내역 버튼이 중복되어 하나의 보조 기능이 두 번 노출됩니다.
- 시작 버튼은 기능상 핵심이지만 현재 `gi-pulse`가 없습니다.

### 문단 읽기·중심 문장

- 문장 카드는 읽기에는 충분하지만, 현재 미션과 단계 정보가 화면 상단에서 분리되어 있지 않습니다.
- 단계 이동 후 제목을 `scrollIntoView({ block: "start", behavior: "smooth" })`로 보내기 때문에 제목이 뷰포트 최상단에 붙습니다.
- `.screen-title:focus { outline: none; }` 때문에 단계 전환 후 프로그램 포커스가 시각적으로 확인되지 않습니다.
- skip link와 `main`의 명시적 id가 없습니다.

### 순서 수리

- 6개 문장 행이 같은 흰색 테두리 상자로 반복되고, 각 행의 숫자 입력과 위·아래 버튼이 좁은 화면에서 조작 밀도를 높입니다.
- 현재 위치 입력과 이동 버튼은 접근성 이름은 있으나, “이 문장을 어디로 옮기는가”가 시각적으로 한 덩어리로 묶이지 않습니다.
- 문단 시험하기 버튼에만 `gi-pulse`가 있어 핵심 행동 강조 계약은 부분적으로 적용되어 있습니다.
- 연속 오답 피드백의 근거가 한 패널에 들어오지만 핵심 문장·힌트·다음 행동의 대비가 약합니다.

### 관련성·연결·설명

- 관련성 단계의 “보관함으로” 조작과 빈 보관함 그룹이 같은 무게로 보여, 문장과 보관함의 관계가 약합니다.
- 연결 관계 선택은 제품적으로 중요하지만 일반 선택 버튼 묶음으로만 보여 선택 전·후의 작업 상태 차이가 작습니다.
- 설명 단계의 `수리 완료 확인`에는 `gi-pulse`가 있으나, 선택 전 비활성 상태에서도 화면의 다음 행동 안내가 충분하지 않습니다.

### 학습 기록

- 6개 미션의 첫 순서와 최종 순서를 모두 보여 주는 제품 계약은 좋습니다.
- 현재는 동일한 미션 카드가 길게 이어져 세션 전체를 마쳤다는 요약과 각 기록의 읽기 우선순위가 약합니다.
- 교사 검토 전 콘텐츠라는 정직한 안내는 있지만, “이번 세션에서 무엇을 기록했는가”와 “다음에 무엇을 해 볼까”가 구조적으로 분리되지 않습니다.

## 4. 기술 감사 점수

점수는 0~4이며 4가 가장 안정적인 상태입니다. 이번 점수는 변경 전 기준선입니다.

| 영역 | 점수 | 근거 |
|---|---:|---|
| 접근성 | 2/4 | semantic label·대화상자 포커스 트랩·키보드 테스트는 있으나 skip link 부재, 포커스 윤곽 제거, 단계 제목 상단 잘림 가능성이 있음 |
| 성능 | 3/4 | 로컬 WebP 하나와 정적 번들, 외부 요청 없음. CSS 배경이 전체 shell에 적용되고 장식 자산의 정보 가치가 낮음 |
| 테마 일관성 | 3/4 | 토큰 파일은 있으나 화면 CSS에 raw `#eef4fb`가 남고, 배경 아트와 실제 카드 언어가 충돌함 |
| 반응형 | 2/4 | 기본 wrap은 있으나 보고서 외 명시적 breakpoint가 적고, 320px 순서 조작·상단 작업 정보·행 밀도 규칙이 부족함 |

| **합계** | **13/20** | 기능은 안정적이나 첫 화면, 단계 orienting, 모바일 작업면, 피드백 계층을 전면 정리할 가치가 큼 |

## 5. 우선순위별 문제와 제안

### P0

이번 기준선에서 기능을 막는 P0는 확인되지 않았습니다.

### P1

| 문제 | 왜 중요한가 | 제안 |
|---|---|---|
| 첫 화면의 좁은 중앙 열과 배경 아트 충돌 | 시작 전에 앱의 작업 목적보다 장식이 먼저 읽힘 | “교실 편집 데스크” 레이아웃으로 hero·미션 rail을 2열로 재배치하고, 장식 이미지는 실제 UI처럼 보이지 않는 저대비 주변 자산으로 교체 |
| 현재 미션·현재 단계 위계 약함 | 학생이 지금 6개 중 어디인지와 무엇을 하는지 동시에 판단해야 함 | 미션 번호/관계/진행을 하나의 작업 헤더로 묶고, 단계 내비게이션에 숫자·완료·현재 상태를 추가 |
| 단계 전환 시 제목이 잘리고 포커스가 보이지 않음 | 키보드 사용자와 화면 확대 사용자가 맥락을 잃을 수 있음 | `scroll-margin-top`, reduced-motion에 따른 auto scroll, visible focus ring, `main#main-content`, skip link 적용 |
| 순서 수리 조작 밀도 | 핵심 학습 조작이 320/375px에서 행 단위로 읽히지 않음 | 문장 카드·현재 위치·이동 조작을 하나의 작업 그룹으로 묶고, 작은 폭에서는 조작을 명시적 두 번째 줄로 배치 |
| 피드백과 다음 행동의 시각적 우선순위 약함 | 근거를 읽은 뒤 무엇을 눌러야 하는지 망설일 수 있음 | 피드백을 “판정/근거/다음 행동” 3층으로 나누고, 현재 단계의 유일한 주요 CTA만 `gi-pulse`로 강조 |
| skip link 부재 | 반복되는 헤더를 건너뛰기 어려움 | 첫 포커스 가능한 요소로 “본문으로 건너뛰기” 제공 |

## 6. 유지할 긍정 요소

- `missions.ts`가 미션 콘텐츠와 허용 순서를 한곳에서 관리해 리디자인이 학습 정답을 손상시키지 않도록 하기 좋습니다.
- 순수 evaluator와 reducer가 화면에서 분리되어 있어 UI를 크게 바꾸면서도 기능 검증을 유지할 수 있습니다.
- `aria-label`, `aria-pressed`, 입력 라벨, 대화상자 포커스 관리가 이미 있어 보강 비용이 낮습니다.
- 서버·브라우저 저장·외부 요청이 없는 경계는 교육용 정적 앱의 신뢰성과 배포 단순성을 높입니다.
- 현재 업데이트 내역과 이미지 rights ledger가 있어 리디자인 산출물의 출처를 추적할 수 있습니다.

## 7. 감사 후 방향 결정 입력

- **제품 은유:** 교실 편집 데스크
- **시각 원칙:** warm ivory / ink navy / muted coral action / sage success; 종이 질감은 보조하고 실제 조작면은 DOM으로 만든다.
- **레이아웃 원칙:** 입장은 2열, 작업 화면은 “단계 내비게이션 → 미션 헤더 → 안내/작업면”, 기록은 세션 요약 후 미션별 기록
- **모션 원칙:** 현재 핵심 CTA 한 개만 `gi-pulse`; reduced motion에서는 애니메이션 제거와 텍스트 표식으로 의미 보존
- **리디자인 금지선:** 기능 로직·고정 콘텐츠·개인정보 계약·VoiceOver 제외 정책·원본 자산 보존을 바꾸지 않는다.
