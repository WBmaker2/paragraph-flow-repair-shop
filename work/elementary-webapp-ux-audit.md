## 2. 실제 브라우저 기준선

### 입장 화면, 1280×720

- 제목 `문단을 읽고, 근거로 고쳐요.`, 첫 미션 문장, 6개 미션 목록, `활동 시작하기`가 실제 DOM과 화면에 표시되었습니다.
- 첫 화면의 시각 위계와 미션 장면 이미지는 안정적이었고, 이미지가 장식으로만 사용되었습니다.
- 콘솔 오류는 관찰되지 않았습니다.

### 입장 화면, 375×812

- 브라우저의 실제 문서 폭은 360px이었고 `scrollWidth === clientWidth`였습니다.
- `활동 시작하기`는 첫 viewport 안에 표시되었습니다.
- 첫 화면의 문장과 버튼은 읽을 수 있었지만, 헤더·목표·설명·4개 목표가 이어져 있어 첫 행동 뒤의 실제 작업 위치는 스크롤을 더 해야 확인됩니다.

### 첫 미션, 320×800

- 브라우저의 실제 문서 폭은 305px이었고 `scrollWidth === clientWidth`였습니다.
- 단계 제목 `전체 읽기`와 6단계 순서는 보였지만, 현재 작업 표면의 장식 `수리 메모`가 문장·선택지보다 먼저 배치되었습니다.
- 실제 DOM에서 `.workbench__guide`가 `.workbench__task`보다 먼저 나타났고, 첫 판단 버튼은 viewport 아래에 있었습니다. 측정 시 `guide`의 viewport top은 566px, `task`는 899px, 첫 판단 버튼은 1,561px이었습니다.
- 이 상태는 숨김·잘림은 아니므로 P1로 과장하지 않지만, 6개 미션의 모든 단계에서 핵심 행동을 반복해서 찾게 만드는 P2입니다.

### 완료 기록 화면, 375×812

- 6개 미션 기록, 처음 순서·최종 순서, 판단·관계·근거가 실제 화면에 표시되었습니다.
- 상단 요약의 `근거 기록 / 다음 글에도 가져갈 생각`은 전이 의도는 있으나, 다음 글에서 무엇을 할지 한 번에 실행할 수 있는 전략은 아닙니다.
- 6개 기록 뒤에야 `처음부터 다시 하기`가 나타나므로, 완료 직후의 학습 전이를 상단에서 강화할 여지가 있습니다.

### 전체 학습 경로

신선한 로컬 탭에서 `활동 시작하기`를 누른 뒤 6개 미션을 모두 통과해 `수리 기록`까지 도달했습니다. 각 미션은 중심 문장 선택, 순서 시험과 유예, 관련성 보관함, 연결 표현, 관계 선택을 실제 버튼으로 조작했습니다. 375px에서 `scrollWidth === clientWidth`였고 콘솔 오류는 없었습니다.

## 4. 이슈 장부

### EDU-UX-001 — P2 — 좁은 화면에서 장식 안내가 실제 과제보다 먼저 나옴

- **Path/state:** 입장 → 1번 미션 → 전체 읽기, 미응답 상태
- **Persona/viewport:** 초3–4 준호 / 320×800, 375×812
- **Observed action/result:** 단계 제목까지 이동한 뒤 `수리 메모`와 도구 이미지가 먼저 길게 나오며, 문장 선택지와 판단 버튼은 여러 화면 아래에 위치
- **Evidence:** 실제 DOM 순서 `.workbench__guide` → `.workbench__task`; 320px에서 guide top 566px, task top 899px, 첫 판단 버튼 top 1,561px; 가로 넘침은 없음
- **Learner impact:** 학생이 지금 읽고 눌러야 할 대상을 찾기 위해 매 단계마다 긴 장식 구간을 통과해야 함
- **Root-cause hypothesis:** 데스크톱 좌측 안내의 DOM 순서를 모바일에서도 그대로 세로 쌓음
- **Proposed change:** `max-width: 900px`에서 실제 과제 표면을 먼저 배치하고 수리 메모·도구를 뒤로 이동. 장식과 안내는 보존하되 행동 위계를 우선
- **Verification:** 동일한 시작 상태와 320/375px에서 첫 선택지·첫 CTA 위치, 전체 경로를 재확인
- **Status:** fixed

### EDU-UX-002 — P2 — 완료 직후 다음 글에 적용할 방법이 추상적임

- **Path/state:** 6개 미션 완료 → `수리 기록`
- **Persona/viewport:** 초3–4 준호, 초5–6 서윤 / 375×812 및 데스크톱
- **Observed action/result:** 상단 요약은 `근거 기록 / 다음 글에도 가져갈 생각`으로 끝나고, 구체적인 다음 읽기 순서가 없음
- **Evidence:** `이번 세션 요약` 직후 3개 요약 셀, 하단에는 `처음부터 다시 하기`만 있음
- **Learner impact:** 활동에서 익힌 순서·관계·근거를 다음 문단에 옮겨 쓰는 방법을 스스로 회상해야 함
- **Root-cause hypothesis:** 기록 화면이 회고 자료에는 집중했지만 transfer cue를 별도 구조로 만들지 않음
- **Proposed change:** 상단에 `다음 글에 써 볼 방법`을 추가하고 `중심 생각 → 문장 관계 → 근거`의 3단계와 짧은 실천 문장을 제공
- **Verification:** 동일한 6개 미션 완료 후 상단 첫 viewport와 DOM에 takeaway가 있고, 인쇄·재시작·기록 내용은 유지되는지 확인
- **Status:** fixed

### EDU-UX-003 — P2 — 일부 완료·상태 문구가 학습 행동으로 바로 이어지지 않음

- **Path/state:** 관련성·완료 기록
- **Persona/viewport:** 초3–4 준호 / 320–375px
- **Observed action/result:** `관련성 점검`, `수리 이유`, `교육 모형은 실제 세계 전체를 보장하지 않아요` 같은 표현은 문맥을 읽어야 이해됨
- **Evidence:** 실제 learner-facing DOM과 inventory 후보. 단계 힌트가 일부를 풀어 주지만 완료 화면에는 추상적인 주의 문구가 남음
- **Learner impact:** 핵심 교과어휘와 운영 안내를 같은 무게로 읽으며, 다음 행동의 의미를 다시 해석할 수 있음
- **Proposed change:** 이번 사이클에서는 완료 화면의 주의 문구만 아동 친화적으로 다듬고, 교과어휘·버튼 계약은 기능 테스트와 콘텐츠 검수 후 별도 변경
- **Verification:** before/after 문구 상태별 렌더링, 교과 정확성 human-review, 오답·완료 경로 재확인
- **Status:** fixed for the completion notice; button-label simplification remains a follow-up candidate

## 5. 자산·시뮬레이션 판단

기존 미션 장면 아틀라스·도구 이미지는 현재 제품의 맥락과 잘 맞고, 이번 이슈의 원인은 이미지 부족이 아니라 모바일 배치입니다. 새 이미지는 생성하지 않습니다. 장식 제거 후에도 학습 문장과 판정은 유지됩니다.

문단 수리 활동은 문장 순서·선택·근거를 직접 조작하는 정적 학습 흐름입니다. 시간에 따른 연속 변수, 물리 모델, 관찰값 비교가 없으므로 시뮬레이션은 `not-needed`로 결정했습니다. 상세 결정은 [`elementary-webapp-ux-simulation-decision.md`](./elementary-webapp-ux-simulation-decision.md)에 기록합니다.

## 6. 이해 점검

- **지시 재진술:** `전체 읽기`의 “문단 전체를 먼저 읽고, 처음 느낌을 기록해요”는 다음 행동을 말할 수 있었습니다.
- **결과 예측:** 선택 버튼을 누르면 `선택됨` 상태와 `다음` 활성화가 나타나는 것을 관찰했습니다.
- **용어 설명:** `중심 문장`은 입장 화면의 “중심 생각으로 이어진 글”과 단계 힌트로 추정할 수 있으나, `관련성`은 `흐름과 관계없는 문장` 설명을 함께 읽어야 합니다.
- **회복 행동:** 순서 시험을 두 번 미달시키면 `함께 다시 볼 근거예요`와 `다음 단계로`가 나타났고, 관련성 오답은 보관함에서 문단으로 돌릴 수 있었습니다.

## 7. 이번 사이클의 수용 기준

- 320/375px에서 `.workbench__task`가 `.workbench__guide`보다 먼저 읽히고 첫 핵심 조작이 장식 뒤로 밀리지 않음
- 6개 미션 전체 경로, 오답·유예·뒤로 가기·보고서가 기존과 같은 의미로 유지됨
- 완료 기록 상단에 구체적인 학습 takeaway가 보이고, 인쇄·재시작 동작이 유지됨
- 아동 친화적으로 다듬은 문구는 목표·판정·개인정보 경계를 왜곡하지 않음
- `scrollWidth === clientWidth` at 320/375px, 콘솔 오류 없음, 기존 자동 검증 모두 통과
- VoiceOver는 계속 범위 밖이며, 키보드·DOM 이름·포커스는 기존 계약으로 확인

## 8. 개선 후 검증

### 실제 브라우저

- 320×800: `workbench__surface`의 DOM 자식이 `workbench__task → workbench__guide` 순서가 되었고, task top 566px, guide top 1,434px, 첫 판단 버튼 top 1,228px으로 확인되었습니다. 기준선의 guide top 566px/task top 899px/첫 판단 버튼 top 1,561px보다 실제 과제가 먼저 나옵니다.
- 375×812: task top 540px, guide top 1,355px, 첫 판단 버튼 top 1,148px이며 `scrollWidth === clientWidth`입니다.

- 375px 전체 경로: 입장 → 6개 미션 → `수리 기록`을 다시 실행했고, 보고서 상단에 전이 카드와 새 범위 안내가 표시되었습니다. 전이 카드는 top 416px, height 440px로 첫 보고서 viewport 안에서 확인되었습니다.
- 업데이트 내역: `2026-08-31 — 모바일에서 실제 과제를 먼저 보여 주고 다음 글에 적용할 읽기 전략을 추가`가 최신 항목으로 표시되었습니다.
- 콘솔 오류: 기준선·개선 후 모두 관찰되지 않았습니다.

| 맥락적 시각자료·자산 안전 | 5 | 5 | 새 이미지 없이 기존 장식 자산과 DOM 학습 정보 경계 유지 |
| **합계** | **100** | **91** | P0/P1 없음, 핵심 게이트 통과 |

최종 판정은 `pass`입니다. P2 수준의 버튼 문구 통일 후보와 실제 학생·교사 검수는 남아 있지만, 핵심 경로·모바일·키보드·전이·자산 안전 게이트를 모두 확인했습니다.
